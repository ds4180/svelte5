# 📑 프론트엔드 복원 및 아키텍처 기록

> 본 문서는 파괴된 프론트엔드 인증 및 데이터 구조를 표준 아키텍처에 맞게 재건축한 기록입니다.

---

## 1. 개요 (Overview)
- **작업 목표**: 클라이언트 사이드 인증 로직(`onMount` 등)에서 발생하는 무한 리다이렉트 루프 해결 및 서버 기반의 표준 인증 체계 확립.
- **표준 근거**: `아키텍처 세션 관리 및 토큰 유지 전략.md` (제1관문: handle, 제2관문: handleFetch).

## 2. 핵심 구현 아키텍처
### 2.1 레이아웃 그룹 격리
- **`(app)` 그룹**: 인증이 필요한 서비스 경로(`/v1/*`).
- **`(auth)` 그룹**: 인증 진입점(`/login`).
- **상태 관리**: 서버 데이터를 `+layout.server.js`에서 주입받아 `$effect`로 클라이언트 `authStore`와 즉시 동기화.

### 2.2 인증 엔진 이관 (Server Hooks)
- **`hooks.server.js`**: 
    - 페이지 단위 리다이렉트를 제거하고, `handleFetch` 훅에서 API 응답(401) 기반으로 인증을 처리하여 리다이렉트 루프 방지.
    - **경쟁 상태 제어(Locking)**: `isRefreshing` 락을 통해 다중 API 호출 시 중복 토큰 갱신 차단.
    - **데이터 클로닝**: `request.clone()`을 사용하여 인증 재시도 시 원본 요청 유지.

### 2.3 프론트엔드 데이터 바인딩
- **CRUD 고도화**: Svelte 5 룬 문법(`$state`, `$effect`) 도입으로 데이터 바인딩 반응성 보장.
- **데이터 흐름**: `서버 세션 검증` → `+layout.server.js (User 로드)` → `+layout.svelte (UI 렌더링)` 순으로 흐름 정립.

### 2.4 세션 안정화 및 고도화 (Session Stabilization)
- **세션 고도화**: 액세스 토큰 5분, 리프레시 토큰 3일 정책 적용.
- **실시간 연장 (Advanced Sliding Window)**: 인증이 필요한 모든 API 요청(`get_current_user`) 시마다 Redis 세션 만료 시간을 마지막 접속 시점으로부터 다시 3일로 자동 연장하도록 백엔드 로직 고도화.
- **쿠키 동기화**: 프론트엔드 서버 훅(`hooks.server.js`) 및 클라이언트 스토어(`authStore.js`)에서 백엔드 정책과 동일한 `max-age`(5분/3일)를 가지도록 쿠키 설정 로직 통일.
- **결함 수정**: 
    - `fetch` URL 내 템플릿 리터럴 문법 오류(따옴표 불일치) 전수 조사 및 수정.
    - 루트 레이아웃(`+layout.svelte`) 내 `initializeAuthStore` 참조 누락 해결.
